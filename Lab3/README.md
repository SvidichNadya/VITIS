# LMS SFEDU — Playwright Lab 3

Учебный набор автотестов для `https://lms.sfedu.ru/`.

## Структура тестов

### Functional — функциональная проверка сайта

Файл: `tests/functional.spec.ts`

Сценарии повторяют реальные публичные пользовательские действия LMS:

1. главная страница → проверка публичного содержимого и состояния гостя;
2. каталог курсов → проверка актуальных категорий;
3. поиск курса → ввод запроса и переход на страницу результатов;
4. страница входа → классическая форма, @sfedu-вход и восстановление пароля;
5. пустая авторизация → проверка обработки некорректного ввода;
6. восстановление пароля → username и email;
7. последовательная навигация главная → каталог → вход.

Функциональные сценарии не используют реальные учетные данные и не изменяют учебные данные.

Для каждого ключевого сценария в HTML-отчет прикладываются:

- пошаговые `test.step`;
- screenshot фактического состояния страницы;
- URL;
- HTML страницы;
- JSON с ожидаемым результатом и выполненным действием.

Поэтому после запуска можно открыть `playwright-report/index.html`, выбрать тест и последовательно посмотреть, что именно сделал браузер и какое состояние сайта было получено.

### Security — безопасный security smoke / black-box

Security-тесты находятся в отдельных `security.*.spec.ts`.

Они проверяют только безопасные публичные свойства:

- границу авторизации;
- security headers;
- session-cookie attributes;
- отсутствие очевидного раскрытия SQL/stack trace;
- open redirect;
- безопасные признаки XSS;
- CORS;
- доступность `.git/HEAD`;
- HTTP TRACE;
- единичный baseline-запрос для наблюдения времени ответа.

На production LMS не выполняются brute-force, нагрузочные атаки, массовое перечисление, destructive POST, изменение/удаление данных или эксплуатация найденной уязвимости.

Проверки, которым нужен тестовый аккаунт, явно пропускаются без `TEST_USER` / `TEST_PASS`.

## Запуск

Установка:

```powershell
npm install
```

Функциональные тесты:

```powershell
npm run test:functional
```

Security:

```powershell
npm run test:security
```

Всё:

```powershell
npm run test:all
```

Интерактивный режим:

```powershell
npm run test:headed
```

HTML-отчет:

```powershell
npm run report
```

По умолчанию используется установленный Google Chrome через Playwright `channel: "chrome"`.

Для другого стенда:

```powershell
$env:BASE_URL='https://example-test-stand'
npm run test:functional
```

## Как читать результат

Не каждый failed test автоматически означает дефект LMS.

Для функционального теста:

1. открыть тест в HTML-отчете;
2. посмотреть `test.step`;
3. открыть screenshot и HTML evidence;
4. при падении открыть trace;
5. сравнить фактический URL, текст и состояние элементов с ожидаемым действием.

Для security:

1. открыть attachment с evidence;
2. проверить HTTP status, headers и body;
3. посмотреть annotation/finding;
4. только после воспроизведения считать результат подтвержденной уязвимостью.

## Важно

Security smoke checks рассчитаны на безопасное, неразрушающее тестирование. Не добавляйте сюда brute-force, нагрузочные атаки, удаление/изменение данных, эксплуатацию найденных уязвимостей или обход авторизации без явного разрешения владельца системы.
